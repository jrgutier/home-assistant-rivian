
## 2026-08-18 — s08a complete (3/4 fixtures), + a retracted diagnosis

### The websocket was never broken
Reported earlier as "the Parallax real-time path is dead on this account". FALSE.
The live instance logs ~13,639 state changes/24h. What was actually happening:
the gateway permits exactly ONE active subscription per user session token. HA held
it; every local probe was the second connection, which the server accepts, never
acks, and closes at TTL with 4420. A malformed token by contrast gets 4403 in 0.5s.
Proven by disabling the HA entry: ack arrived immediately, twice.

Also retracted: "the access token expired and nothing refreshes it". The client
authenticates on session tokens only and never sends Authorization: Bearer
(see `git show dev:src/rivian/rivian.py` ~line 181, and BEARER_TOKEN_TEST_RESULTS.md
:49-50). A-Sess is _app_session_token, minted fresh by create_csrf_token -- NOT the
OAuth access token. No refresh mechanism is needed or wanted.

### Two defects the merge introduced or exposed, NEITHER flagged by git
1. cover.py duplicate frunk. Upstream defines frunk unconditionally under
   COVERS[None]; our fork had moved it behind the FRUNK_NXT_ACT feature. The merge
   kept both, so a vehicle with that feature registers TWO entities keyed "frunk"
   (duplicate unique_id). It arrived through an AUTO-MERGED region -- no conflict
   marker, no test failure until the entity-count assertion caught it. This is the
   silent-gain class the plan warned about, observed for real.
2. ws_monitor.py imported WSMessageTextBytes from aiohttp.http_websocket at runtime
   for an annotation only. HA pins aiohttp==3.12.15, which lacks it, so `import
   rivian` raised ImportError under HA -- upstream 2.1.0's client CANNOT LOAD IN
   HOME ASSISTANT. Inherited from upstream unchanged. Fixed in the client repo
   (c587a79) by moving it under TYPE_CHECKING.

### Landmine worth knowing (pre-existing, NOT introduced here, NOT fixed)
Home Assistant's DataUpdateCoordinator defines its own _update_interval_seconds
(update_coordinator.py:83) and overwrites it in __init__. Our coordinators declare
a class attribute of the SAME NAME. It works only because line 67 reads the class
attribute while building super().__init__()'s arguments, before HA's __init__ runs.
Every later read of self._update_interval_seconds -- including _set_update_interval
at :78 -- sees HA's value, not ours. Assert coordinator.update_interval instead.

NOT pushed, so the pin will not resolve until a human pushes vendor-client in the
client repo. s07 removes the pin entirely by vendoring.
