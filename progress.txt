## 2026-08-18 — w07: reconnect storm fixed (client repo e9363d9)

ws_monitor.py recognised ONE close reason, the string "Unauthenticated". The codes
the server actually sends (all MEASURED, not read off the spec) are 4401
Unauthorized, 4403 Forbidden, 4408 init timeout, 4420 TTL expired. None matched, so
an auth rejection was retried as if transient -- and `attempt = 0` ran as soon as
the socket OPENED, which it does before the server rejects, so the exponential
backoff was reset every cycle and never applied. A 4403 arriving 0.5s later gave an
unbounded tight reconnect loop against Rivian's API.

Now: 4401/4403 stop the monitor and log at error; 4420 is routine recycling;
backoff resets only once the connection is ACKNOWLEDGED; backoff_delay() extracted
so the policy is testable without patching asyncio.sleep.

### Two testing lessons worth keeping
1. My first backoff test was VACUOUS -- it passed with the bug restored, because the
   fake socket reported closed=True and so exercised the pre-existing early-backoff
   branch rather than the new ack-gated one. Only mutation testing caught this.
   A test that cannot fail is worse than no test: it reads as coverage.
2. My second attempt assigned to `rivian.ws_monitor.asyncio.sleep`. That module
   attribute IS the global asyncio module, so it patched asyncio.sleep
   process-wide and broke asyncio.wait_for -- the test hung instead of failing.
   Patch YOUR OWN module's symbols; never a stdlib module's attributes.
   The test now bounds itself from the reconnect side, because without the ack gate
   the monitor never reaches an await that yields, so wait_for can never fire and
   the regression would surface in CI as a hang rather than a failure.

Client suite 119 -> 137. HA suite 989, coverage 78.73%.

## 2026-08-18 — s06b: watchdog de-duplicated, diagnostics extended

### The watchdog now exists once
Lifted into RivianDataUpdateCoordinator. Two near-identical ~50-line copies
remained after s06a dissolved the third with ParallaxCoordinator; they differed
only in log wording and ONE behavioural rule.

That rule is preserved as an override, not a copied loop:
  VehicleCoordinator._watchdog_skip_reason() -> "vehicle is sleeping"
ChargingCoordinator deliberately has NO skip: a charging session continues while
the vehicle sleeps, so the same rule would stop watching an active charge. That
asymmetry is now stated in code and pinned by a test, rather than being an
accident of which copy someone edited.

### _watchdog_tick() is a seam, and the reason matters
The existing test test_watchdog_logic_restarts_when_stale re-derived the trigger
conditions in the test body -- asserting `time_since > timeout` and concluding
"this validates that the watchdog WOULD restart". It cannot fail when the watchdog
logic changes, which is the only thing it exists to protect. Extracting one tick
makes the real logic drivable without waiting out the 60s loop OR patching
asyncio.sleep globally (which broke wait_for session-wide earlier today).
13 contract tests now exercise it, parametrised across both coordinators.

### Diagnostics
Parallax data already reaches the dump via the vehicle/charging coordinators, so
the useful addition was the part that is otherwise invisible: whether the
subscription is live, which topics were requested, and which are decodable.

## 2026-08-18 — s10: protobuf is gone

The package encoded exactly ONE message -- ClimateHoldSetting, a single int32 --

generated code refuses to load when its gencode is newer than the runtime, which

### Golden bytes first, because there is no round trip
There is no write-side decoder, so decode(encode(x)) == x is unavailable and the
golden bytes ARE the entire safety net. Captured from the generated classes BEFORE
deleting them, across a 14-value grid including the 127/128 varint boundary.

five-minute hold, and 08a038 (7200s) is in SENDVEHICLEOPERATION_TEST_RESULTS.md.
google.protobuf.Timestamp is replaced by ~20 lines, pinned against four captured
encodings -- including the epoch, which encodes to NOTHING because proto3 omits
defaults, and sub-second nanos.

The .proto files REMAIN the documented wire format. The script no longer writes
into the package; it regenerates into a temp dir and re-asserts the golden bytes,
so the .proto files cannot quietly drift from what is actually encoded.
